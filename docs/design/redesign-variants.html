Blogmark · design review

Amplitude vs Bindery

Two complete directions for the app, built to be chosen between. Both are minimalist without going inert, both replace the current three-language icon set with one system, and both give their single colour exactly one job — which is the direct answer to the thing most wrong with the app today.

Palette

Why

The problem isn’t taste, it’s that there is no system

Reading the screens alongside the theme layer, the visual faults all trace back to one cause: the design exists as repeated code rather than as shared components. There is no card composable, no chip, no button — so every screen re-invents them slightly differently.

  • Everything is a card, so nothing isHome gives all four sections the identical rect, fill, hairline and orange eyebrow. No hierarchy, nowhere to land.
  • The accent stopped meaning anythingFour orange eyebrows down one screen, plus orange links, bookmarks and dots. An accent on everything is just body colour.
  • Three icon languages at onceFine outline strokes, a filled triangle for play, and literal glyph stand-ins (<>, ♪) that read as placeholders.
  • Metadata is a run-on2026-08-22 · 1:22 · summary · codeword · 682 words — five facts at equal weight above the fold of every row.
  • Monochrome is subtractionIt’s the colour theme with the orange deleted, which is precisely why it reads as boring. It has no idea of its own.
  • The card recipe is copy-pasted nine timesAcross DashboardTab, FollowingSection, ReaderTab, SettingsScreen and LinksTab. Six near-identical chips live in six files.
  • The type scale is bypassed 44 timesNine ad-hoc inline sizes in circulation. 12.5.sp appears eight times — a token nobody named.
  • The launcher mark is a speckThe artwork fills only ~15% of its 108dp canvas, so the fanned stack collapses to a blob at launcher size.
  • Focus is a word in a voidAn outsized wordmark centred on an otherwise black screen, with three low-contrast orange pills beneath it and no timer in sight until it runs.
  • Empty states sit dead centreA 92 dp badge a third of the way down, then 60% blank — and centred, which quietly breaks the project’s own lower-third rule.
  • Cards nested inside cardsFollowing is a bordered card full of bordered post cards, so borders double up and the row of tiles is sliced off at the screen edge.
  • The floating bar does two jobsThree navigation tabs, a divider, then a theme toggle — a preference living inside a navigation component, justified by a hairline.

The two directions

One hue, one meaning — twice over

Each direction picks a different true thing about the app and lets it drive everything else. Both are dark-only, so the phone frames below keep their own palettes whatever theme you are reading this page in.

Use the palette control at the top to re-tint both directions at once — including back to the terracotta the app ships today, so you can see each proposal wearing the current colour. Only the colour variables change; no structure moves. That is deliberately the test: a direction that only works in one hue is a paint job, not a system.

Amplitude

Colour appears only where there is sound.

IdeaThe app’s genuinely unusual trait is that it reads text aloud. So the interface is greyscale, and the one hue is spent entirely on audio — playing state, position, level. Colour can never drift into decoration because there is only one place it is allowed to go.
TypeJost for display and UI — a 1920s geometric with real character, used at light weights. Inconsolata for every number and label.
DeviceThe waveform is data: bar heights are the clip, filled bars are the position. It is never an ornament.
Icons1.75 stroke, butt caps, miter joins — drawn with a rule. Play becomes a stroked triangle so it finally joins the family.

Bindery

Read things recede. The one colour means done.

IdeaThe other true thing: this is a shelf. Items arrive, wait, get read, and leave. So state is made physically legible — unread items hold full contrast and weight, read items dim and go italic. Verdigris marks completion and nothing else.
TypeSource Serif 4, drawn for extended reading, for every title. Karla for UI. No monospace at all — metadata is Karla with tabular figures.
DeviceRules, not boxes. Section labels sit above a hairline; a firmer rule marks a real break. Recession does the sorting.
Icons1.5 stroke, round caps and joins throughout — drawn with a pen. Again no filled exceptions.

Proposed — on-device summary

The one feature the app is actually missing

Readback items arrive with a summary already written, because readback wrote one before the library was ever synced — that tab is a read-only import and stays one. Everything else in the app has no summary at all: saved links and followed-feed posts carry a title and whatever description the page’s metadata happened to offer. That asymmetry shows on every screen. Gemini Nano closes it for every article the app knows about, and closes it on the device — which is the only way it could be closed without contradicting the app’s own promise that there is no account and nothing leaves the phone.

The design problem it creates is more interesting than the plumbing. Each direction has just committed to one colour meaning one thing — so a new feature must not arrive carrying a colour of its own. Both frames below hold the line, and are better for it.

The summary is set as marginalia — indented behind a rule, in the reading serif, italic. A note written in the margin of the page, which is exactly what it is. No colour needed, so verdigris still only ever means finished.

What it would actually take

API ML Kit GenAI Summarization — com.google.mlkit:genai-summarization. Summarizer + SummarizerOptions with InputType.ARTICLE and OutputType.THREE_BULLET, which is the same shape Pixel Recorder used for its three-bullet transcript summaries. runInference(request) { newText -> } streams, which is what makes the generating state above worth designing.
Where Android only, so it lives in androidMain behind an expect/actual — the pattern the repo already uses for rememberReadRepository and ReaderSourcePicker. Desktop, iOS and Wasm get a no-op actual and simply never show the affordance.
The catch This is the real work, and it is not the model. Blogmark stores a URL and its metadata, never the article body — for saved links and feed posts alike — and the summariser needs at least 400 characters of clean prose, ideally 300+ words. So extraction comes first, and it is the piece worth designing carefully: feed entries sometimes ship full content in the RSS payload and need no fetch at all, while a bare saved link needs fetch plus readability. The HTTP client already exists for feed sync and title backfill; the extractor does not.
Limits About 4000 tokens in, roughly 3000 English words — the 2020-word Flink piece fits, longer ones need setLongInputAutoTruncationEnabled(). English, Japanese and Korean only.
Device gate Needs AICore and a supported Tensor, Snapdragon or Dimensity part, API 26+, locked bootloader. checkFeatureStatus() returns UNAVAILABLE / DOWNLOADABLE / DOWNLOADING / AVAILABLE. On an unsupported phone the button should not exist rather than exist and fail — and the first run needs a download state, since the LoRA adapter is fetched on demand.
Why it fits The app already says there is no account and nothing leaves the device. An on-device summariser is the only kind that keeps that true, so this is a feature the product’s existing promise argues for rather than merely tolerates.

Icon set

Same geometry, two different hands

Both walls below are drawn from one shared set of paths — only the stroke width, cap and join differ. That is the discipline missing today, where ten of seventeen stroked icons set a line join, two set neither cap nor join, and Play/Pause are filled while everything else is stroked. Amplitude’s hand is not settled yet — three candidates are drawn out below.

Amplitude — 1.75 stroke, butt cap, miter join

Bindery — 1.5 stroke, round cap and join

Amplitude — three hands

One geometry, three ways of holding the pen

Bindery’s hand is settled — 1.5, round cap and join, to match a serif that has no hard terminals. Amplitude is the one still open, because its icons sit next to a waveform and have to agree with it. All three walls below draw the same fourteen shapes; only the instrument changes. Each is repeated at 17 px in the real nav bar, which is the only size that actually decides this. Fourteen glyphs is enough to judge a pen — the full 24-glyph list, and three sets that change the drawings rather than the instrument, are below.

Line — 1.75, butt cap, miter join

The default hand, and the one the rest of this document is drawn in. Butt caps and mitred joins give it the same squared-off ending as the waveform bars, so a nav icon and a clip share a terminal shape. Weakest at 17 px: the clock and the settings dials thin out against a dark ground.

Solid — filled silhouette, no stroke

No line width to get wrong. Counters — the door, the clock hands, the crescent in contrast — are punched out with evenodd rather than drawn, so every glyph stays one closed shape. Holds its weight at nav size better than either stroked hand, but it is heavier than the type, and Amplitude’s whole argument is that the chrome should sit under the text.

Segment — broken strokes, gap at every junction

Corners are never closed: each glyph is assembled from separate strokes with a deliberate gap where they would meet. That makes the icon set built from the same vocabulary as the waveform — discrete bars with air between them — rather than merely sitting beside it. The risk is legibility: folder and external are close to the point where the gaps stop reading as style and start reading as a rendering bug.

Where this lands: segment, with line as the fallback. Solid is the most legible of the three and the least Amplitude — it competes with the type for weight, and the variant’s one rule is that nothing outshouts the words except sound. Segment earns its place by being the only hand that is derived from the waveform rather than compatible with it; if the gaps prove fragile on a real device at 17 px, line is a one-line CSS revert, not a redraw.

Amplitude — three alphabets

Three different drawings, not three pens over one

The section above changes the instrument and keeps the shapes. This one changes the shapes. Each set below is generated by a single construction rule — stated beside it, and checkable against every glyph — and each covers the full 24-glyph list the app actually needs rather than the fourteen a pen study needed: transport (skip, back, speed, sleep), library (search, queue, share, delete, add) and state (offline) are all new here. Both bars beneath each wall are at 17 px, the real size.

Rule — Horizontal, vertical, 45°. Nothing else.

The rule: no curve exists in this set. Circles are octagons, the clock is a facet, contrast shades with hatching instead of a fill, and feed is three nested right-angle brackets rather than three arcs. Amplitude’s ground is graphite and its face is Jost — a geometric sans built from the same three angles — so the set reads as an instrument panel, which is what a playback app drawing real waveform data actually is.

COST  feed and offline lose the radio metaphor entirely; the octagons need a device check — at 17 px they may just read as badly-drawn circles.

Bar — The waveform is the alphabet.

The rule: anything that can be built from evenly spaced vertical bars is — readback, feed, offline, settings (the sliders are bars), and the shading on contrast. What cannot be built that way borrows the same 2.4 weight and round terminal so the set still looks cut from the same clip. This is the only one of the three that could not belong to any other app.

COST  heaviest of the three — it competes with the type, which is the same objection that sank Solid. feed and offline are one slash apart, which is the point but puts real weight on the slash.

Arc — Every corner is a quarter-circle.

The rule: nothing closes on a hard vertex. Same corner radius throughout, so the door of home is an arch, the play triangle has rounded points, and speed is a gauge sweep rather than a chevron pair. The soft pole, and the one a stranger would read fastest cold.

COST  the least distinctive. Drawn well, but it is the set every app already ships — nothing about it says this app.

Where this lands: Bar, and it is not close — it is the only set derived from the thing the app is for, and Amplitude’s whole argument is that the waveform is the interface. But it inherits Solid’s problem, so it wants the lighter end of its weight range before it ships. Rule is the interesting second: it fights the waveform rather than echoing it, which is a legitimate different answer. Arc is here as the control — if neither of the other two survives a device check this is what is left, and it is fine, and fine is the whole objection to it.

If you pick one

The follow-on work is the same either way

Whichever direction wins, the structural fixes underneath it are identical — and they are the reason the drift happened in the first place.

  1. Extract the four missing components into ui/common/ — SectionCard (or its rule-based replacement), Chip, PillField, IconButton. That removes nine copies of the card recipe and six near-identical chips.
  2. Name the orphan sizes into the scale. Nine ad-hoc values disappear into five roles; 12.5.sp in particular is used eight times and has simply never been given a name.
  3. Settle the mono question. Amplitude needs no bundled mono at all if the data face is Inconsolata; Bindery needs none by design. Either way Mono = FontFamily.Monospace goes, and with it the per-platform metadata typeface.
  4. Fill the unset colour slots. Only about 15 of ~30 ColorScheme entries are defined, so the rest are still Material baseline purple. Also worth fixing: surfaceVariant is currently darker than background, inverting elevation.
  5. Reconcile the three grounds. The app uses #101010, the web shell #0c0f14 and the in-app browser pure #000000. One token, three places.
  6. Redraw the launcher artwork to fill its canvas and regenerate the adaptive icon, the iOS 1024 slot, the web favicon and the splash from the same source.
  7. Article extraction is the prerequisite for on-device summary, not the model. Nothing ships until saved links and feed posts carry readable body text; the ML Kit call itself is a few dozen lines behind an expect/actual. Worth checking the RSS payload for full content before fetching anything.
  8. Tidy the strays — the dead Layout token object, the unused CodeStyle, the AlgoTypography name, the orphan Blogmark.icns, the raw tween values in the tab transition, and the one Icons.AutoMirrored.Filled.OpenInNew that slipped past the icon rule.
