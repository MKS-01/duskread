Blogmark · design system

Amplitude

Greyscale interface, one hue, and that hue means exactly one thing: there is sound here. This page documents the design language as it actually ships today — real tokens, real layouts, real icon set — plus what's genuinely still open.

This replaces docs/design/redesign-variants.html, which compared Amplitude against a second direction ("Bindery") to decide between them. That decision is made — Amplitude shipped — so the comparison page is retired. Screen-by-screen migration history lives in docs/design/amplitude-migration.md.

Reader toolbar, not the list. A summary needs Article.text, which only exists after extraction — running that (and a local-model pass) for every row in Saved or Readback would mean summarising links nobody opens. The button lives beside the existing Reader-view toggle, hidden (not disabled) until extraction has produced text, matching that toggle's own rule.

Inline spinner, not a blocking screen. The article is already readable while the model runs — the icon swaps for a small spinner in the same 34px slot, nothing else on screen changes.

Floating, not full-screen. Same instinct as the toast and the nav bar: a panel that sits over the reader rather than replacing it, dismissible with the corner close glyph or a tap outside, so checking the summary never costs your scroll position in the actual article.

The model: ML Kit's on-device GenAI Summarization API, Android-only, behind an expect/actual the way ReadRepository and AudioPlayer already are — other platforms would hide the button the same way Readback's folder picker differs per platform today. The prerequisite, Article.text, already exists; nothing about extraction is new work.

Monochrome

Ink — a second design, not the first one with the colour deleted

The hue drops to nothing and level is carried by luminance alone — the interface was already greyscale, so the idea survives intact. Reachable from the tab bar's contrast toggle or Settings; the choice persists across restarts and flips the Android launcher icon and splash to match.

Brand

A mark that survives 48px

A level meter whose tallest bar is a bookmark — the notch reads as both a ribbon tail and a peak, folding save and listen into one silhouette. Fills roughly 70% of its canvas, solid rather than stepped in alpha, since a bar held at 45% barely separates from a near-black ground at launcher size.

Brand — three new mark concepts (idea, not built)

What the shipped mark doesn't say yet

The shipped mark folds save and listen into one silhouette. It says nothing about Focus — a named, core screen now, not an afterthought — and it's the only one of the app's four facets missing from the brand. These three try different answers, not a single direction to converge on; primitives only (rects, circles), so what's drawn here is exactly what would render, no hand-fit curve that looks different at 24px than it does at 132.

Focus frame. Viewfinder brackets — the one universally legible "focus" glyph — around a single waveform bar. The only concept of the three that puts Focus in the mark at all, at the cost of losing the bookmark reference entirely; whether that trade is right depends on which facet the brand should lead with.

All three keep the shipped mark's actual constraints: solid fill (no alpha steps — they vanish against near-black at launcher size), the same terracotta, and an Ink pass exactly like the shipped mark's own (swap #c6684a for #dcdcdc, nothing else changes). None of this is built or decided — a direction should get picked, then get the same safe-zone scale and splash-settle animation treatment the shipped mark already has, before anything here touches ic_blogmark_mark.xml.

Naming ideas

Not proposed as a rename — the app is called Blogmark throughout this document and the codebase, and nothing here should be read as deciding otherwise. Kept as a small, separate list of directions that occurred alongside the mark exploration, in case a mark and a name ever get reconsidered together rather than one at a time.

  • Cadence — the rhythm across a read, a listen and a Focus session; pairs naturally with a mark built from bars.
  • Tempo — one syllable, ties directly to the timer as much as to audio.
  • Marginalia — the notes a careful reader leaves in the margin; literary, matches an audience that reads engineering blogs closely.
  • Waypoint — a saved link as a point returned to, doubling as a checkpoint for a focus session.
  • Longform — states plainly what the app is for: posts worth the whole read, not a skim.

Icon set

Bar — the waveform is the alphabet

One stroke spec throughout: 2.4 weight, round cap and join. Every glyph that can be built from evenly spaced vertical bars is — readback, feed, offline, settings (the sliders are bars) — and the rest borrows the same weight and terminal so the set still looks cut from one clip. This is the mockup's original demo wall, kept as the stroke reference — it is not a mirror of ui/theme/BlogmarkIcons.kt. The shipped set is 20 icons and diverges both ways: search, share, sleep, speed, skip, queue, offline, add and delete below were never built (no playback-speed, sleep-timer, search or share feature exists), while the code has several this wall doesn't show — Target, Clock, Shuffle, FolderConnect, BookmarkFilled, Reader, Check.

Type

Jost + Inconsolata, five roles

Jost for display and UI — a 1920s geometric with real character, used at light weights. Inconsolata for every number and label, so data never has to borrow the platform's default mono.

In use today

What's actually shipped

Cross-checked against the current codebase, not carried forward from the old migration notes unverified.

  • No card boxes anywhere. Home, Readback, Saved, Following and Settings all sit flush on the background, separated by a bottom hairline (ui/common/ListRow.kt). The Following post carousel and feed-management list, once boxed, are flat now too.
  • One shared row skeleton. ListRow/ListRowBody/ListRowDivider hold the sourcechip-title-meta shape everywhere it appears, instead of three hand-rolled copies. RowTone (Normal/Accent/Faded) names the states a row can be in.
  • Two colour schemes, real tokens. ui/theme/Theme.kt's DarkScheme (Paper Black, terracotta #C6684A) and MonoScheme (Ink) — both dark, mono is the same layout with hue drained to luminance alone.
  • Ink persists and reaches the launcher. The toggle (tab bar or Settings) is saved via UserPrefs and survives restarts; on Android it also flips a pair of activity-aliases (LauncherPaper/LauncherInk) so the home-screen icon and splash match.
  • Radius.Chip (3dp) is the shared corner for anything hairline-bordered and squared-off: sort chips, the sourcechip, and — as of this pass — the Settings and folder icon buttons, both now bordered squares rather than bare glyphs.
  • Jost + Inconsolata throughout, replacing Space Grotesk and each platform's default mono.
  • BlogmarkIcons.kt holds 20 stroked vector icons in the Bar hand (2.4 weight, round cap/join) — see the Icon set section above.
  • The floating nav bar carries three tabs, the transport when something's playing, and the Ink toggle behind a divider.
  • AppTextField is the one text-field shape in the app — hairline border, Radius.Inline (10dp), never a pill — used by every field: Saved's paste field, the feed-follow field, Settings, the desktop folder path, onboarding, and Focus's new custom-length entry.
  • Launcher icon and splash fill ~70% of their canvas, solid rather than alpha-stepped, animating the outer bars to rest on boot.

Next

Genuinely still open

Re-verified against the current code — some items the old migration notes flagged (Readback's sort pills being filled surfaces, Following still boxed) are already fixed and dropped from this list.

  • Saved's "From clipboard" suggestion and one paste-row fill are still filled surfaceContainer/primaryContainer boxes (LinksTab.kt) rather than a bordered pill.
  • Desktop has no app icon — compose.desktop.application.nativeDistributions sets no iconFile.
  • iOS and Wasm haven't been compiled across this whole design pass — a cold Kotlin/Native build is ten-plus minutes, so it's deliberately been skipped; one run should happen before calling any of this settled on those platforms.
  • Cut features awaiting a call, not a bug: the read-along highlighted-excerpt view and the "Read original" external-link row (both real, both cut when Readback went to two-facts-and-a-waveform), and the floating bar's ambient background waveform (moirés into a hatch at the row pitch).
  • Article summary — see the Screen — Article summary section above for the worked-out idea (entry point, loading state, floating result). Not started; the extraction prerequisite (Article.text) already exists.
